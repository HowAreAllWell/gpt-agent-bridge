# 项目连续性：清单与有条件的状态发布

本共享契约负责清单文件路由、状态与记忆的撰写分工，以及有条件的发布。它只实现项目本地的连续性，不建立全局记忆、共享运行时身份或持久的 Agent/Work 身份。

规范清单指向规则、一个当前状态文件和一个记忆文件。当前状态是普通 UTF-8 文本，可以没有槽位。规范清单不带版本；加载器拒绝任何版本字段。本公共仓库不附带实际的 `.principal/`；每个项目须在明确授权下创建自己的目录。本共享契约描述源码中的路由和发布行为。规则保留其原有权威；清单路由不会分配角色或授予任务权限。

状态是唯一可替换的当前判断位置：项目走到了哪里、尚未解决的依赖、下一步行动或边界，以及恢复工作所需的前提。记忆保存持久的因果选择、仍然有用的长期边界、证据定位信息和重新审视的条件。两者都不是对话记录或由解析器管理的台账。不要求固定的 Markdown 区域或字段结构，也不提供自动归档或共享记忆。

`context(project_ref)` 返回有界的指针和 SHA-256 修订值，不返回状态正文。清单缺失或无效会被报告，但不妨碍普通 context 使用。`project_register` 返回已连接项目引用的 Project Binding 补充文本，供用户在 ChatGPT Project 一侧应用，并返回持久化分类；它不创建连续性文件。`project_initialize` 为已注册项目发布全新的规范 `.principal/` 目录，或保持已有规范清单不变。若 `.principal` 尚不符合规范，则拒绝且不覆盖。初始化种子必须指定已存在的规则文件；只有提供有实际内容的 `project_rules_content` 时才写入 `.principal/rules.md`。发布通过一次不替换目标的目录重命名完成。重命名之后不会删除该目录。响应丢失不能证明目录不存在。指针必须是有界的相对路径，并拒绝路径穿越、`.git` 和符号链接。

`current_state_update(project_ref, expected_revision, content=None, edits=None)` 仅有条件地替换或创建声明的状态文件（UTF-8，最多 65,536 字节）。使用你实际读取文本的修订值；`missing` 允许不覆盖已有目标的创建。现有的每工作树单进程写入门将协作调用串行化。过期修订会失败且不覆盖状态：重新读取，协调双方贡献，再针对相应修订提交协调后的文本。已有文件发布会在原子替换前立即复查哈希；这不是针对外部写入者或其他进程的全局 CAS。传输丢失使发布结果不确定：先读取，再决定下一步。它不意味着自动重试。

<a id="canonical-manifest"></a>

## 规范清单

加载器只接受一种结构。必需键为 `rules`、`current_state` 和 `memory`；不接受其他键。没有版本字段，也没有 takeover 字段。

- `rules` 是非空文件路径列表。
- `current_state` 和 `memory` 是文件路径。
- 版本键、takeover 键、slot 键、已退役的 `methods` 键（即使为空或 null）以及任何其他键，都会触发拒绝。
- 状态、记忆和规则的路径各不相同；都不能指向清单本身。
- 指针总上限为 16，包含状态和记忆。它们是文件指针，不是目录或流程发现机制。

重复 JSON 键、重复列表项、未知字段以及无效的路径、类型或数量都会触发拒绝。路径必须由 Unicode 标量组成；转义的孤立代理项会被拒绝。清单上限为 8192 字节，路径上限为 512 个字符。检查限于仓库本地，不跟随符号链接，并要求每个规范指针指向普通文件。发布前必须能读取规则和记忆；只有状态缺失时才允许沿用现有的不覆盖创建路径。指针检查不返回任何文档正文，也不认证记忆或规则内容的真实性或其 UTF-8 编码。

Context 在 canonical_pointers 中展示规则和记忆，不增加清单版本。状态 SHA/修订值的展示保持不变。current_state_update 使用相同的有条件发布、UTF-8/整文件限制和可选的文件内槽位检查。它只写 current_state，不写记忆、规则或清单。不会自动引入槽位或文件，也不提供多文件迁移或事务。

<a id="opt-in-publication-slot"></a>

## 自愿采用的发布槽位

当前状态文件可以选择使用一个机械槽位。标记必须独占整行，不支持转义、嵌套或第二个槽位：

```
<!-- bridge-state-slot start limit=N -->
```

```
<!-- bridge-state-slot end -->
```

`N` 是从 1024 到 65536 的规范十进制整数，不带正负号或前导零。槽位正文是从起始行的 LF 或 CRLF 结束符之后，到结束行首字节之前的精确 UTF-8 字节切片。正文内部的换行结束符计入长度；标记行和标记对之外的字节不计入。长度按字节而非 Unicode 标量计算。单独的 CR 不是行结束符。只有去除 LF 或 CRLF 后的整行是以 `bridge-state-slot` 开始的 HTML 注释时，才算类似标记的行。较长行中的提及，包括在注释前还有代码围栏的行，都不是标记。代码围栏不会隐藏独占一行的标记；第二对标记属于重复，会被拒绝。

此检查适用于完整内容、精确编辑和缺失文件创建，在修订匹配后、任何写入前执行。它不摘要、截断、归档或提交。拒绝会返回 `CheckpointSlotRejected` 和有界的 `slot_reason`，且不写入任何内容。

- 当前文件缺失，或存在但没有类似标记的行：无槽位的候选内容仍按旧式替换处理。若候选恰好有一个有效槽位且正文不超过 `N`，则采用该槽位。含畸形类似标记的候选会被拒绝。
- 当前文件有一个有效槽位 `N`：候选必须仍恰好是同一个有效槽位 `N`，正文最多 `N`。移除、扩大、缩小、重复、额外或畸形标记，以及超限正文都会被拒绝。同一个 `N` 的槽位可在文件中移动；正文和外部字节可以变化。
- 当前文件含畸形的类似标记字节：发布可将其修复为干净的无槽位文件，或一个正文不超过其 `N` 的有效槽位。畸形候选仍会被拒绝。
- 65,536 字节的整文件上限保持不变，与此槽位不同。

此保护适用于 `current_state_update` 及其协作发布调用者。`project_text_edit`、git 和外部编辑器不执行它。修改已采用的 `N` 或移除槽位不属于此发布原语；其他编辑器不会因绕过检查而获得任务授权。这个通用机制仍供自愿采用的项目使用；默认合成夹具没有槽位。工具不判断文笔，也不自动保留被替换的历史。

必须且只能提供完整 `content` 或非空 `edits=[{old_text,new_text}]` 之一。每个 old_text 必须非空，在同一个原始状态中唯一，并且与其他编辑不重叠。全部替换只针对该原始版本应用一次，保留其他 UTF-8 字节，包括 CRLF。匹配缺失、不唯一或模式混用都会失败。编辑不能创建缺失的状态。Read 的 `file_sha256` 加上 `sha256:` 前缀，可提供实际读取字节的修订值；inspect_file 本身不读取状态。current_state_update 不意味着任何 Git 版本操作。project_text_edit 在任务范围内另行允许对已有项目 UTF-8 文件进行精确编辑，包括所有者文档；它不改变清单路由、撰写责任或当前状态的创建/修订语义。获准冻结版本时，commit_prepare 选择字面文件路径并冻结评审候选，再由 commit 精确发布该候选。两种工具都不认证声明，也不自动归档尚未提交的因果主线。

内容属于 `principal_supplied_unverified`；文件系统哈希只证明字节，不证明真实性。current_state_update 不执行命令、暂存或提交 Git、摘要、截断、授予新权限，也不把传入声明提升为事实。现有任务授权仍适用；没有额外的角色、审批或权限系统。槽位检查仅涉及字节与限制值的身份一致性。

<a id="authoring-and-preservation-boundaries"></a>

## 撰写与保留边界

替换状态不会归档此前未提交的字节。持久的原因可在现有任务授权下写入记忆文件，与只写声明状态的 current_state_update 分开进行。没有多文件事务：在目标位置和可恢复版本确认之前，所需的内联原因仍有保留价值。读回只证明字节和指针，不证明真实性或之后成功恢复工作。

Git 历史是已提交因果信息的默认归档；独有的外部或运行时证据可能需要单独保留产物。定位信息应指明目标版本。动态运行时事实和进程本地 Work 引用不会因写入文字而成为持久身份。历史验收不能认证当前部署或客户端缓存的工具结构。

获得单独授权后，提交可提供可恢复的字节定位信息；本共享契约不授予长期提交权限。撰写是在判断哪些信息会改变下一步决策，不是每轮仪式或强制发现台账。没有持久变化，就不需要新增记忆条目。

新 Chat 的实用性需要未经额外指导的真实接手者，依据发布的判断位置、证据与权限边界，选择合理的下一步工作。源码与传输测试检查信息保留，不证明宿主发现、Skill 激活、推断质量或真实新 Chat 验收。

## 可复用流程与本地认知

[Bridge Plugin Skills](TECHNICAL-REFERENCE.zh-CN.md#native-skills-and-app-binding) 负责仓库内可复用的 Principal 流程。项目指令保留范围和权限；经路由的状态、记忆和规则仍留在本地。Principal Methods 及其清单路由已退役；初始化种子也拒绝任何 `methods` 字段。含此字段的已有清单必须在任务授权下明确编辑；初始化会拒绝已有的非规范目录，而不是修复它。不提供兼容别名或替代的流程路由字段。源码测试检查清单路由和字节保留，不证明宿主 Skill 发现、自动触发可靠性或更广泛的接手者实用性。路由不分配角色或授予新权限。Skills 独立于连续性清单路由；不会引入运行时 Skill 加载器。
