---
name: project-onboarding
description: Connect an existing local Git repository to Bridge or initialize fresh canonical project continuity when the user requests onboarding. Do not initialize an already canonical project or create a repository under this workflow.
---

Confirm the authorized `project_ref` and existing repository root. Register with
`project_register` only if needed. Inspect registration and continuity with
`bridge_overview` and `context`; respect uncertain persistence/publication results.
A host-side Project Binding amendment must be applied by the user where required.

For requested fresh continuity, seed from actual existing project facts: genuine
rule paths, its current decision position and durable causes. Supply project rule
text only when real project-specific guidance needs that layer. Never invent an
`AGENTS.md`, copy another project's cognition or seed speculative history.

Use `project_initialize` for an already registered project. A canonical manifest
already present is a no-op; a noncanonical directory is refused. Do not delete or
replace existing cognition to force initialization. Inspect an uncertain outcome
before another mutation, then verify the returned routing and published content.

Registration and initialization grant no project role or task authority. If only
connection was requested, stop after registration and its binding handoff.
